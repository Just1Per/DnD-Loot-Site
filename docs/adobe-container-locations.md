# Clear container locations — v94

**Containers** above Equipment, Extra Equipment and companion sheets opens the existing owned-container dialog as a readable overview. Show extra features → Sheet choices → Containers & item locations reaches the same view. No new catalogue, ownership record, page or provider is introduced.

The overview groups carried owned items by their actual carrier and displays individual containers with their own capacity, direct contents, nested location paths, stack quantities and loose items. Search includes item/container names, parent paths and location notes. Duplicate container names on the same carrier have numbered labels. Empty containers remain visible. Physical source weights supply capacity figures; unknown weights and overload remain visible. A meter caps its visual fill at full capacity while the text retains the real overload. A container without a verified weight capacity is labelled explicitly.

Open an item to see its actual path, for example `You → Backpack → Pouch`, and a separate **Location note**. Gear-row menus, owned-item information and companion equipment show the same summary. Typed paper/location text is a note and does not assign the stack to a real container. Saved unavailable/cyclic placements display as loose with an explanation; opening the dialog does not rewrite them.

Choosing a destination previews the resulting path and capacity through the existing pure placement rules. **Apply placement** changes the existing private association; Cancel/Escape or Reset leave it unchanged. Navigation refuses to discard a changed placement choice silently. Returning to the overview retains the search. Apply still requires **Save sheet** for persistence. Cycle/nested-magical/cross-carrier rules remain authoritative; excess capacity is a warning, never removal. Carrier changes use the existing companion transfer flow.

The original paper names/amounts, row layout, column weights and printed artwork are retained. The overview control lives in the nonprinting heading. Actual stock, attunement, charges, notes, equipped effects and physical carrying calculations use the existing helpers. There is no data migration, schema change, rule deployment or new dependency. Volume and compartment modelling remains separate backlog.

Regression coverage: pure active/inactive/nested/carrier location descriptions without mutation; connected production headings and row/item entry points; grouped contents and capacity; independent notes; draft preview/Cancel/Reset/navigation; retained search; explicit Apply and private save/reopen; cycle/unavailable/stale/detached/session-close guards; 320/390px layouts, keyboard/focus and axe. The pinned-item, companion-equipment, paper-gear and print flows remain separate regression checks.
