# Subclass feature coverage audit

Generated from the selectable subclass catalogue and the pinned 5etools cache. The audit compares source identity only: it never copies source entries or feature prose.

A source match does **not** mean that feature rules are present in the application. “Alternate source” means the same class/subclass exists in the pinned cache, but under a different book identifier.

- **Partial mechanics**: War Domain has its grants, War Priest resource, Channel Divinity choices, Divine Strike reminder and Avatar of Battle resistance in the rules engine. Table decisions still remain manual.
- **Reference only**: the sheet has a level-by-level feature list, but no complete source-specific mechanic adapter.
- **Not in runtime**: selectable in Character Builder, but has no subclass feature rows at runtime.

## Findings

1. The imported/staged 5etools metadata is correctly suited to source identity and catalogue browsing. It intentionally does not include feature entries or mechanics, so it cannot fill the runtime gaps by itself.
2. The next implementation work should start with subclasses that players can select but that have no runtime feature list. Add a reviewed feature adapter per subclass; do not execute or display upstream source entries.
3. Base-class features are inventoried separately in [character-class-level-review.md](character-class-level-review.md). Its current base-class review contains 27 edition/source cases and 540 class-level checks, but does not certify subclass mechanics.
