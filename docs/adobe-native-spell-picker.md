# Native Adobe spell selection

In Adobe preview, open a spell page and choose **Choose spells**. The button is available in the single-page toolbar, above each caster's page in All sheets, and on the original paper. The page's caster is selected initially. No Standard panel opens for selection. Existing Generate/update actions also delegate to this dialog while Adobe is active; Standard retains its existing generator.

The dialog offers **Available spells** and **Your selection**, with name/search, reachable spell level and school filters. Exact names rank first. Clicking a name previews casting time, range, components, duration, description and source before choosing it. On mobile, the reference opens as a detail view with **Back to spells**. Results are rendered in batches of forty.

The existing CharacterSpellcasting profiles, casting statistics, automatic grants and CharacterCatalog filters remain authoritative. A multiclass caster selects from its own class-level reach, even if shared slots are higher. Class switching retains each draft. Wizard spellbook minimums are guidance; preparation is bounded. Known/fixed-prepared classes limit selected spells. For prepared classes (including Cleric), the level 1+ reference list is separate from daily preparation: add eligible spells without automatically preparing them, then check Prepared. On sheet counts the reference entries; Prepared counts only checked ordinary spells against the class allowance. Wizard uses the same preparation controls with its separate spellbook minimum. Cantrip limits are unchanged. The shared Standard generator preserves these flags too. Automatic grants are separate and locked. The existing generator uses the same shared selection validation helper.

Existing manual, unassigned, duplicate and unavailable records are retained. An imported over-limit pool may stay unchanged or decrease, but cannot increase. Manual/unassigned spell authoring is outside this picker. New choices follow current campaign sources and edition; source-specific Artificer fallback follows the existing catalogue policy.

**Apply to sheet** updates only the character's spell array. **Save sheet** persists it. **Cancel** or Escape discards the dialog draft. Actor/session changes, concurrent character or inventory changes and policy changes are checked before applying. Selection does not spend spell slots, restore resources, grant feats or modify campaign data. Ordinary and Pact slot controls keep their separate existing route.

No Firestore/Storage rule, schema, index or production migration is required. This closes the native selection bridge; it does not complete every source spell tool, custom spell editor or the full 1:1 conversion.

Verification covers shared pool limits/grants and inherited exceptions, Wizard preparation/book behavior, Cleric reference lists larger than the preparation allowance in both editions, separate preparation/swap/save/reopen/Cancel and domain grants, Standard round trips, multiclass selection/reach, private save/reopen, cancellation, unchanged HP/coins/ordinary/Pact slots and inventory, retained manual/unassigned notes, actual PDF exclusion of unapplied picks/UI, mobile/accessibility, and stale/session cleanup.

Daily preparation is also available directly on the original paper: click the circle beside a spell, or focus it and press Space. A filled circle is prepared; an empty circle is not. This works in Single page, All sheets and continuation pages with the correct caster/offset. The existing shared preparation action enforces the class limit and updates both views without opening an editor or generator. Always-prepared grants are locked and cantrips/known/fixed-prepared spells have no daily preparation toggle. Save sheet persists changes.


## Source generator and printed references — v84

Each spell-sheet heading now offers **Generate spell sheet** alongside **Choose spells** and the readable spell list. The source review has Class, Race and Feat steps with Previous/Next navigation. Class choices use the same searchable picker. The race step opens the existing ancestry-choice draft; the feat step opens existing feat choices. These dialogs have their own Apply/Cancel boundaries. Applying a class selection opened from the guide returns to the source review. Save sheet remains the persistence action.

**Origin of Entry** appears in selection rows, source review, readable references and printed source headers. Live, validated racial magic, Magic Initiate choices and class/subclass grants have generated references without requiring a manual copy to the spellbook. Race/feat pages retain their own casting ability, attack modifier and DC. Their free-use state and casting restrictions remain with their original source; creating a sheet does not refresh or spend them. Other spell-granting feats still use their existing supported controls/reference notes; this work does not invent missing feat mechanics.

**Spell sheet display** is a per-class private preference: Selected spells, Prepared spells only (prepared classes/Wizards), and Full reachable class list (prepared classes only). Full lists include eligible level 1+ spells at that class's own spellcasting reach, plus saved entries and live grants; they do not learn unchosen cantrips, grant off-list spells, populate a Wizard book, or broaden known/fixed-prepared classes. Generated references do not consume the 150 saved-spell budget. Clicking a preparation circle for a full-list reference explicitly saves and prepares just that spell, checking the ordinary allowance and storage bound atomically. Prepared-only output preserves the saved unprepared entries and notes.

Generated source/list references are read-only and open normal spell information. Saved spell rows retain their editable text. Loss of the source removes its generated references; existing personal/saved rows are retained. Source policy, compatible edition, actual class level and subclass ownership/unlock are checked before generating new references. An expanded subclass list offers ordinary choices; it is not an automatic grant. The 2014 Fiend regression verifies that distinction.

The preference remains inside the existing private Adobe envelope. No schema, Firestore/Storage rule, index or catalogue migration is required. Regression coverage includes both editions, multiclass reach, locked grants, source abilities, revoked grants, display/Cancel, direct preparation, saved notes/resources, save/reopen, mobile accessibility and actual connected PDFs.
