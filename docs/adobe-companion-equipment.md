# Companion equipment — v85

The original MPMB 13.0.4 companion template contains a hidden `Comp.eqp.Image`, 17 `Comp.eqp.Gear` rows with amount/unit weight, a subtotal, 17 `Comp.eqpB.Gear Button` arrows, and `Comp.eqp.Notes`. These overlap the large ordinary notes field. The restored layout is exported statically from the supplied original PDF; no Acrobat JavaScript, character values or full rule entries are executed/copied. `scripts/build-adobe-companion-equipment.py` regenerates the blank image and metadata and is also called by the general page exporter.

In an ordinary owned Gear row, choose **Move owned item to a companion**, review the named carrier and entire owned quantity/weight, then confirm. Cancel changes nothing. Worn/equipped items must be unequipped first. Copied references and automatic attunement/footer rows retain their existing reference workflows; use the original owned row to move a stack. Partial-stack splitting is outside this change.

The destination opens at its original row. Its arrow opens equipment controls with current physical load, capacity/status, paper fields, movement between companions and return to Equipment/Extra Equipment. Empty companion arrows and Manage equipment on shared companion cards can move an existing owned row into the first empty slot. Full 17-row companions and full original character destinations refuse without overwriting anything. A Wild Shape reference is not a separate carrier. Unknown weights remain explicit; overload is recorded as a warning rather than silently changing quantities.

The row stays associated with the same owned ID. Quantities, Library snapshots, personal item descriptions, attunement, charges, spell slots, HP and coins are not rewritten. Each item is assigned to at most one companion after normalization. Physical load uses live owned quantities and unit weights once; character carried weight excludes assigned stacks, and companion load includes them. Capacity uses that companion's recorded Strength and size, including the verified catalogue Mule's Beast of Burden size step. Magical containers, class-specific companion scaling and item bonuses for the companion are not invented. Carrier labels also appear in shared inventory. Its explicit Move to backpack action returns the assignment, and marking a personal item uncarried releases it to storage rather than leaving a stale companion load.

Paper names, amount, unit weight and location overrides travel independently. Inline companion fields retain the same bounded validation and invalid-draft protection as character gear. Their subtotal uses paper amount × unit weight (blank amount is one; 0 is none). Changing an annotation does not change stock or physical load. Character section subtotals/selected weights exclude references to a companion-carried stack, including copied representations. The character's attunement list remains an owned-item reference and still consumes its normal slot.

Assigned equipment cannot be equipped on the character until returned. Derived armor, weapon and worn magical effects also reject forged assigned/equipped combinations. Attunement and stored item counters remain intact. Companion equipment does not automatically apply the item's mechanics to that creature.

Existing companion notes are reused in the right-hand notes box; the large original notes field is hidden only while the equipment layout is present. Neither changing the creature nor moving an item replaces its HP, scores, attacks, features or notes. Hiding a page preserves assignments. Removing a companion restores every assigned item to available character equipment space (including continuations if needed); refusal at the global paper limit leaves the creature intact. Other companion records retain their own equipment even when their array position changes.

Assignments live with each companion inside the existing private Adobe envelope. No schema, Firestore/Storage rule, index or production migration is required. Apply updates the draft; Save sheet persists it. Actor, campaign, inventory, companion and pending-field guards reject stale actions. Closing the sheet disposes the dialog. Connected printing uses the same original equipment artwork, fields and retained notes. A small web load/capacity readout uses the free left side of the subtotal line so physical load remains visible separately from paper annotations.

Validation covers pure transfer/weight/normalization/capacity/full-target invariants, live stock changes, unavailable references, independent notes/resources, forged equip combinations, both rule editions, actual pointer and inline field edits, Cancel, companion-to-companion movement and returns, private save/reopen, companion removal, stale/session cleanup, mobile accessibility and actual PDFs.
