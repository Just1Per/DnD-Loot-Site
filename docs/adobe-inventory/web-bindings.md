# Adobe web function ledger

This supplements the reproducible [static inventory](README.md). Its 567 pushbutton occurrences include repeated templates and artwork. The inventory's `Unmapped` entries are a scanner review queue, not a live implementation status. This ledger records the concrete web behavior and remaining gaps; a related-editor link is **partial**, not proof that the original menu has been reproduced.

The live contracts are `character-adobe-fields.js`, `character-adobe-view.js` and the shared controllers they call. No Acrobat JavaScript runs in the web app.

### Companion maximum HP — v41

The original `Buttons.Comp.Use.HP.Max` menu and shared card action use the same private companion record. Existing creatures default to Manual final maximum. Average/fixed/maximum choices use all creature Hit Dice with its own Constitution and a bounded explicit extra adjustment; unlike a player character, the first die is not maximized. Average rounds once after summing. One-shot totals retain the selected automatic method and expire when relevant inputs change. Missing creature metadata retains the cached total and preference, with Manual available rather than guessing dice. Direct paper/shared maximum edits use the same bounded controller. Current HP, temporary HP, death saves, used dice, other companions and character resources remain untouched. Catalogue replacement keeps its existing explicit reset behavior and uses the new calculated maximum when automation was selected.

This does not automate class-specific companion HP scaling or execute original callbacks. Class-linked creatures can retain a Manual final total. Preferences stay in the existing private Adobe grants envelope; no new Firestore/Storage rules, schema, indexes or migration. Pure tests cover all 127 catalogue creatures, rounding/minima, overrides, unavailable metadata and state isolation; the connected browser check covers native/shared choices, direct validation, persistence, both prints/actual PDF, mobile/axe and stale/account guards.

### Modifier and skill-option menus — v42

The original Set Modifier operation now has a shared native dialog, opened from the Adobe tools or a supported calculated field (Shift/Ctrl/Cmd-click, double-click, Enter). Standard exposes the same controller under Abilities & skills. It retains automatic class/feat/item grants, shows the original manual bonus/current total, previews the result, provides a calculation/training-origin explanation, applies atomically and offers Cancel or restore-original. A Standard numeric bonus edit clears that field’s expression and returns it to a fixed value.

The expression grammar supports the six standard ability modifiers, Prof, original short aliases, adjacent ability abbreviations, arithmetic/parentheses and pipe-separated min/max. Companion variables use that creature; `oStr`/`oProf` refer to the character. Numeric literals round as the original validator; formula totals floor. Input length/token/depth/magnitude and division are bounded. Invalid future contexts retain the expression and use the original manual value, with a visible explanation. No JavaScript, Acrobat callbacks, external lookups or arbitrary field paths run.

Supported fields are six ability saves, eighteen skills, all-skill/tool and all-ability-save extras, initiative, passive Perception, the custom check, additional AC components, a bounded whole proficiency adjustment, stable-source attack hit/damage/dice, nine ordinary slot adjustments for supported spellcasting classes and class-specific spell attack/DC/preparation. Attack changes follow the original owned/manual/action reference through paper ordering, save/reopen and source removal; manual entries remain intact. Dice text supports original C/B/Q cantrip tiers and explicit `=` arithmetic split by underscores. Ordinary slot adjustments use bounded whole numbers; a capacity reduction below spent slots is rejected atomically. Slot/preparation edits do not select spells or recover spent resources, and Pact slots remain separate. Automatic class-granted resource amounts still follow their class rules.

The optional proficiency-dice preference removes fixed training contributions from relevant roll totals, including class-granted death-save proficiency, while retaining fixed proficiency for passive Perception/DCs. Expertise requires two proficiency dice; dice are rolled separately. Source/reference numeric Prof remains available to expressions and class rules. Character and each saved creature have separate preferences. Normal fixed-bonus mode is unchanged.

The original SkillsClick menu now selects alphabetical or ability order and explains automatic/manual training origins. Source row geometry and label overlays move presentation only; proficiency/expertise/bonuses remain on their skill IDs. The same order applies to companion and both Adobe print operations. Class/feat training is edited at its original source.

Show extra features previously led to the feats/items continuation. It now opens the same foldable Sheet tools panel above the paper. Page, zoom and print stay visible; shared character controls, Modifiers and Skill options are grouped inside. Open/closed state is retained locally by user, campaign and character. The PDF button no longer changes the selected page. The tools never print and need no database configuration.

Persisted preferences remain in the existing private Adobe grants envelope; no new Firestore/Storage rules, schema version, index or production migration. Item, Adventure Log and conditional-layout menu operations remain tracked under their separate [backlog points](../adobe-sheet-backlog.md).

Readied spell actions use the same `castingStats` helper as spell pages, including generic/caster-specific attack/DC modifiers and optional proficiency dice. The regression uses legal Wizard/Warlock cantrips plus a prepared save spell and verifies actual readied attack/DC totals, preserved selections/resources and private save/reopen.

## Adobe-native configuration (v43)

After preview testing, the user clarified that every configuration workflow must eventually live in Adobe itself; shared-editor navigation is not completed parity. Level and Class and Levels now open the owned class dialog on a single click or Enter. It owns an isolated draft and reuses catalogue/rule/model functions, without mounting or opening a Standard panel. Rule/subclass minimums, distinct classes, total cap, XP and one-shot allocation, Artificer source-specific subclass caches, invocations and follow-up cantrips, skill training/Expertise/weapon choices, tool abilities and HP review are included. Applied class changes refuse automatic ordinary-slot reductions below spent capacity. Values from other classes and unrelated resources remain saved.

Ability scores, saves and manual skill training likewise have an independent Adobe dialog. Base/final score semantics and point-buy limits use the shared engine; collapsible spreads, effective totals and automatic-training notes are included. Editing a numeric bonus removes only its existing formula. Cancel/stale/authenticated-session guards protect drafts. Existing class/ability shared-editor tests now exercise these native workflows. Origins, full feat/spell/equipment/companion management and remaining shared bridges still need native replacement; do not claim the entire sheet is self-contained yet.

## Native feat configuration (v44)

Feat fields and the Feats tool now open an Adobe-owned draft dialog. It reuses the existing selected-card metadata, effect-control renderer (with an explicit draft parameter), rules catalogue, feat/ASI budget and feature controllers. Selected race/background/class/advancement feats appear first. Granted-choice dropdowns have immediate summaries; information/lookup uses the existing read-only reference. Supported ability, training, Expertise, weapon choices, description-display preferences and simple use counters operate on the local draft. Magic Initiate provides its full existing class/ability/spell/free-use/copy-to-book workflow. Catalogue results are searched/filtered in bounded batches rather than rendering every result. Apply uses the same private save envelope; Cancel/session/account changes cannot apply a stale draft. DM grants/approval administration and the remaining advanced bridges are separate work.

The class Training popup additionally offers the revised Rogue’s granted language through CharacterLanguages.setRogue, preserving Thieves’ Cant itself and rejecting already-known choices.

The Adobe race/background and subclass pickers now hide other-edition options rather than displaying disabled choices. A currently saved compatible legacy selection remains visible until deliberately changed; no data is erased by filtering. Artificer subclasses continue to follow the explicitly selected source version, and revised Artificer is absent under 2014. The native feat catalogue follows the character’s core edition while existing selected feats retain their reference cards.
